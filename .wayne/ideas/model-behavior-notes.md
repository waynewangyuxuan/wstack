# model-behavior-notes

Goal: An agent picking a model in wayne-models can read what each model is like: its strengths, quirks and behavior, across vendors and across models from the same vendor.
Why: Choosing claude, codex, grok or agy, or opus over sonnet, today rests on the agent's guesses; notes from real runs would make the choice deliberate.
Context: wayne-models just shipped ask and batch over four headless CLIs with no per-model guidance; the calling agent picks the model.
